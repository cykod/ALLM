# CLAUDE.md

Guidance for Claude Code working in this repository.

## Project goal

ALLM (Agent LLM) is an Elixir library for provider-neutral LLM execution with first-class streaming and serializable conversation state. The canonical spec is `steering/allm_engine_session_streaming_spec_v0_2.md` — source of truth for module names, types, and behaviour. Target application shapes live in `steering/examples/`.

The package is in initial scaffolding; most modules under `lib/allm/` are skeletons pending implementation per spec §28.

## Architecture in one page

Four conceptual layers — crossing a layer boundary usually signals a design mistake:

1. **Layer A — Serializable data.** `ALLM.Message`, `ALLM.ToolCall`, `ALLM.Request`, `ALLM.Response`, `ALLM.Thread`, `ALLM.Session`, `ALLM.StepResult`, `ALLM.ChatResult`, `ALLM.Event`, `ALLM.Usage`. Plain structs; round-trip through `:erlang.term_to_binary/1` and JSON. No PIDs, refs, funs, or API keys.
2. **Layer B — Runtime.** `ALLM.Engine` plus the `ALLM.Adapter`, `ALLM.StreamAdapter`, `ALLM.ToolExecutor`, `ALLM.ToolResultEncoder` behaviours. Holds non-serializable deps (modules, funs, Finch names, keys resolved at call time).
3. **Layer C — Stateless execution.** `ALLM.generate/3`, `stream_generate/3`, `step/3`, `stream_step/3`, `chat/3`, `stream/3`. Engine passed explicitly.
4. **Layer D — Stateful continuation.** `ALLM.Session.start/stream_start/reply/stream_reply/step/stream_step` over a persisted `%ALLM.Session{}`.

Key invariants:

- **Stream-first.** `stream_*` are the primitives; non-streaming variants are reducers via `ALLM.StreamCollector`. Implement streaming paths first (§3, §28).
- **Event protocol is the wire format between runner and consumers.** `ALLM.Event` is a closed tagged-tuple union (§8). Adding a variant is breaking for reducers; adding a key to an *existing* event's payload map is NOT breaking (pattern-matching on payload keys is non-exhaustive). Document new keys in spec §8 and the constructor's `@doc`. Worked example: `:step_completed` payload grew `:mode` (batch 7.3) to carry `:auto | :manual` to `StreamCollector`'s fold. **Rerouting an existing `Fake` script-entry tag's emission is a separate breaking change from a payload-key addition, even when both ship together** — the additive framing applies to the NEW key only. When a phase also stops an existing entry emitting where it used to (e.g. 21.2 stopped `{:usage, map}` emitting `:raw_chunk` so it could fold onto `:message_completed.metadata.usage`), every existing test site asserting the prior shape is a sites-to-update list and the Test Plan enumerates them as `(MODIFY — semantic change)`.
- **Engines don't carry API keys.** Keys resolve through `ALLM.Keys` at adapter-call time (§6.4). Serialized engine/session must be safe to persist; verify with tests.
- **Adapters MUST document any default they inject for a Layer-A `nil` field that the wire requires.** Anthropic requires `max_tokens`; ALLM Layer A allows `nil`; the adapter injects a default (currently `1024`). The default goes in the public `@doc` of `generate/2` AND the request-builder helper's `@doc false`. Cross-provider divergence on the same field (1024 vs 2048 vs other) is invisible to callers and surprises debugging.
- **Model strings are late-resolved.** Optional `llm_db` provides capability pre-flight and cost population; core must function without it (§6.3).
- **Two orchestration modes.** `:auto` (loop runs tools) and `:manual` (caller submits results). `{:ask_user, ...}` suspension works in both (§12.3).
- **HTTP transport split.** Non-streaming: `Req`. Streaming: `Finch` directly, HTTP/1 (not HTTP/2 — flow-control bug affecting large bodies, spec §7.2).
- **Telemetry is the extension point.** `middleware:` is reserved for later and must stay `[]` in v0.2 (§29). Cross-cutting concerns go through telemetry handlers or adapter wrappers.
- **Mid-stream adapter errors fold into the response, not the call-site tuple.** A mid-stream `{:error, struct}` event surfaces as `{:ok, %Response{finish_reason: :error, metadata: %{error: struct}}}` from `ALLM.generate/3` / `ALLM.step/3` — the call-site tuple stays `{:ok, _}`. Only synchronous pre-flight errors (missing adapter, invalid request, adapter pre-flight failure) surface as `{:error, struct}` at the call site. Callers matching only `{:error, _}` will silently swallow rate limits, content-filter blocks, and stream cancellations. Spec §10.1, PHASE_5 Decision #4.
- **OpenAI has TWO endpoint translators** in `lib/allm/providers/openai.ex` — Chat Completions (`to_openai_messages/1`) and Responses API (`to_responses_input/1`). Anthropic has ONE. Any change to message-content shape, tool-call shape, or system-message handling MUST verify against BOTH OpenAI translators; spec Decisions touching content shape MUST cite both file:lines. Worked example: PHASE_14 Decision #14 cited both translators and shipped zero drift; Phase 10.6's reasoning-control Chat-Completions-only fix needed a Phase 11.x retrofit. PHASE_17 Decision #14 reused the recipe for the Chat-Completions vs Responses content-block divergence (`detail` nested in `image_url` map vs sibling key) — single shared helper `to_openai_content_blocks/2` called from both translators, eight wire fixtures (4 source-shapes × 2 endpoints), zero half-mirror drift. The cross-PROVIDER analogue: when a feature wires in two adapters (e.g., vision input across OpenAI 17.1 + Anthropic 17.2), helper names should align byte-for-byte modulo arity differences driven by per-provider invariants (OpenAI/2 = endpoint atom; Anthropic/1 = single endpoint). 17.1 + 17.2 ship six helper pairs with byte-identical names (`to_<provider>_content_blocks/N`, `part_to_block/N`, `user_content/N`, `reject_image_in_system_messages/1`, `materialize_part(%ImagePart{}) → ""`, `system_has_image_part?/1`); reader pattern-recognition flips immediately between the two files.
- **Files holding parallel streaming + non-streaming paths get analogous treatment to OpenAI's two translators.** When a single file holds both streaming and non-streaming code paths for the same orchestration concept, every Decision file:line cite touching that file MUST disambiguate `(streaming)` vs `(non-streaming)`. A bare `chat.ex:N` cite is drift risk. Canonical pairs: `lib/allm/chat.ex` (`do_step/4` non-streaming + `transition_a_to_b/1` streaming), `lib/allm/session.ex` (`start/stream_start`, `reply/stream_reply`, `step/stream_step` quartet). Worked example: PHASE_18_DESIGN.md:138, :866 cite `chat.ex:1184` ungated; HEAD has neither path's `:manual` short-circuit at 1184 (actual: `:1049` non-streaming, `:1347` streaming).
- **Cross-provider helper-name alignment governs *names*, not *visibility* or *arity*.** After PHASE_17.1 (OpenAI), 17.2 (Anthropic), and 16.4 (Gemini), all three vision-input adapters ship six byte-identical helper-pair names modulo arity (`user_content/N`, `stringify_content/1`, `materialize_part/1`, `reject_image_in_system_messages/1`, `system_has_image_part?/1`, `to_<provider>_content_blocks/N`, `part_to_block/N`). Names align where body shape is shared; diverge with explicit `@doc` justification where it isn't (e.g., 16.5's `to_image_request_body/2` ≠ `to_json_body/2` because Gemini's image gen IS chat translation, not a JSON-body builder). Visibility may differ (`def @doc false` vs `defp`) when local testability needs warrant. Implementer reports use "byte-for-byte" only for literal exact matches; "mirrors X (modulo <delta>)" when alignment is functional-not-literal.
  - **With two capabilities in the tree, a helper sits at the intersection of a *provider* family and a *capability* family, and the two can point different ways.** Name alignment is adjudicated above. **Return-shape alignment is stronger and adjudicated separately: the capability family wins by default** — a name costs a reader one lookup, a return type changes every call site's `with` chain — **and the provider family wins only when a per-provider invariant forces it, with the forcing invariant named in the helper's `@doc false` block.** Phase Module Trees list seams with their return types, not just name/arity, so the conflict surfaces at design time. Worked example: `Gemini.Embeddings.to_batch_body/2` returns `{:ok, map()} | {:error, _}` where the capability sibling `OpenAI.Embeddings.to_json_body/2` returns a bare `map()`, aligning with `Gemini.Images.to_image_request_body/2` instead — forced, because Gemini requires `model` on every sub-request *and* in the URL path, so the body builder is what discovers it absent. `Voyage.Embeddings` has no `Voyage.Images` sibling, so only one axis applies and it takes the capability family.
  - **Within one design doc, a later explicitly-forward-binding block supersedes an earlier checklist line — and the supersession is recorded in the checklist line itself, in the same commit.** A cross-provider seam is named for the neutral concept it converts FROM, not the wire spelling it converts TO: the wire spelling already sits next to every other field name, and concept-naming is what keeps the pair recognisable across adapters. Worked example: PHASE_20.6's checklist specified `to_voyage_input_type/1` (after Voyage's `input_type` wire field) while 20.5's later parity block declared the family member `to_<provider>_task_type/1`; the later block won.
  - **A redaction test with a planted subject binds the pattern, not the leak path.** When a provider's real error text does not echo key material (Gemini's `INVALID_ARGUMENT`, Voyage's `"Provided API key is invalid."`), the `synthesized/error_401.json` fixture must plant a key-shaped token for the redactor test to have a target — correct defence in depth, and NOT evidence that any provider text reaches the redactor. Pair the widened pattern with a companion test asserting the *sibling* providers' patterns match nothing in the same fixture, so an inherited-verbatim regex fails loudly rather than redacting nothing; and state in the parity block which provider-authored channels route through the redactor. Each provider needs its own pattern — `sk-|rk-|org-` (OpenAI), `AIza…|ya29.…` (Gemini), `pa-…` (Voyage) — inheriting a sibling's is a silent no-op.
- **Capability pre-flight runs in `ALLM.StreamRunner` and `ALLM.*` facade helpers, NOT inside adapter `generate/2` / `stream/2`.** Adapter pre-flight handles wire-shape validation only (system-role rejections, MIME, byte size). Direct adapter calls (`ALLM.Providers.OpenAI.generate(req, opts)`) bypass the capability gate by design — callers wanting capability enforcement go through `ALLM.generate/3`. Spec Decisions describing pre-flight ordering MUST cite the file:line where each step actually lives. Worked example: PHASE_17 Decision #7 specified a five-step adapter ladder `(system → capability → MIME → translate → HTTP)` but capability lives at `lib/allm/stream_runner.ex:122`, not the adapter; 17.1 implementer shipped the in-adapter subset and 17.2 added a runner-level capability test (`test/allm/providers/anthropic_vision_test.exs:618-639`) after the steering doc was amended.
- **Layer-A constructors are `struct!/2` pass-throughs by default; runtime type validation is the exception.** `Message.new/1`, `ToolCall.new/1`, `Thread.new/1`, `Response.new/1`, `Request.new/2` all use bare `struct!/2` — type discipline is enforced by `@type t` and callers' Dialyzer, not runtime guards. `Tool.new/1` is the documented exception (`:manual` `is_boolean/1` guard, Phase 18.1, because the Test Plan required `manual: nil → raise ArgumentError`). When adding a new Layer-A field whose type is narrower than `term()`, the Phase Test Plan MUST state explicitly whether the constructor guards or not. Canonical guarded form: `lib/allm/tool.ex:105-121` (this rule cited `:90-99` for months — now the `@doc` examples block. **A file:line cite inherited from an instruction file or a prior design is not pre-verified; instruction-file cites drift as files grow.**)

- **`__from_tagged__/1`'s `data["key"] || default` idiom is wrong for any field whose default is truthy.** The idiom is safe for `nil`, `[]`, `%{}`, `0`, and `false` defaults, and every boolean Layer A field committed before v0.5 defaults to `false` (`Tool.manual`, `Request.stream`, `Request.structured_finalize`, `StepResult.done?`), so it had no counterexample. `EmbeddingRequest.truncate` defaults to `true`, and `data["truncate"] || true` would silently flip an explicitly-persisted `false` back to the default — serializable-state corruption a round-trip test of a *default-valued* struct cannot see. Use an explicit `decode_<field>(nil), do: <default>` / `decode_<field>(other), do: other` pair (`lib/allm/embedding_request.ex`) and pin it with a non-default value in the serialization fixture.

- **Never write a literal `0.0` pattern or function head.** Under OTP 27+ `0.0` matches only `+0.0` and the compiler warns (`pattern matching on 0.0 is equivalent to matching only on +0.0`), failing the zero-warnings gate. Use a `when x == 0.0` guard (`==` treats `+0.0` and `-0.0` as equal), or match `+0.0` / `-0.0` explicitly when the sign matters. Design prose reading "when the value is `0.0`" does NOT transcribe to a pattern. Worked example: `lib/allm/embedding.ex`'s `normalize/1`.

- **Façade `Retry.run/3` collapses an adapter's per-call error sequence — test retryable sequencing against the adapter directly.** `ALLM.generate*` / `generate_image/3` / `embed/3` wrap the adapter in `Retry.run/3`, which transparently retries `:rate_limited` and `{:retry_until_call, n}` returns, so a test asserting a raw `error → error → ok` call sequence is invisible from the façade. Drive `Fake` / `FakeImages` / `FakeEmbeddings` `generate/2` / `embed/2` directly with an explicit `adapter_opts[:cursor_key]` (the value the façade injects via `Engine.put_cursor_key/2`). Where a peek/advance cursor split is involved, a leading non-error entry is load-bearing: it forces `advance` to WRITE the slot `peek` later READS. Worked example: `test/allm/providers/fake_images_test.exs`'s `retry_until_call` test. **Corollary for `embed/3`:** two nested `Retry.run/3` loops (adapter + façade) both list `:timeout` as retryable, so `:timeout` costs 9 attempts per chunk where every other retryable reason costs 3.

Build order (spec §28): data structs → `Engine` → behaviours → `Event` → stream runner + `ALLM.Providers.Fake` → collectors/reducers → streaming APIs → non-streaming wrappers → session helpers → real provider adapters.

## Where things live

- `steering/allm_engine_session_streaming_spec_v0_2.md` — authoritative spec. Cite section numbers in commits and comments (`# see §12.3 ask-user`).
- `steering/examples/` — target application shapes.
- `lib/allm.ex` — top-level facade (§4).
- `lib/allm/` — module tree mirroring spec §27.
- `lib/allm/providers/fake.ex` — deterministic scripted adapter; primary test vehicle (§31).
- **Wire fixtures are stored as `.json`, not `.exs`.** Recorded provider response bodies live under `test/fixtures/<provider>/<endpoint>/<scenario>.json`; synthesized error/edge bodies live under `test/fixtures/<provider>/synthesized/<scenario>.json`. Loaders (`OpenAITestFixtures`, `AnthropicTestFixtures`) read JSON via `Jason.decode!/1`. Design Module Trees specifying `.exs` wire fixtures should be corrected at design time, not by the implementer. Worked example: PHASE_17 §3.5 listed nine `.exs` fixture paths; PHASE_17.1 shipped all nine as `.json` per the Phase 14/15 convention.
- **`mix.exs` `package[:files]` MUST be a superset of `docs[:extras]`.** ExDoc renders `extras:` files into hexdocs at publish time, but the Hex source tarball is gated on `:files` only — a file in `extras:` but not in `:files` ships to hexdocs but NOT to the source download. Verify with `tar -tzf <package>.tar` at release time, not just `mix hex.build` exit-code. Worked example: PHASE_17.3 left `CHANGELOG.md` in `mix.exs:77` `docs.extras` but absent from `mix.exs:69` `package.files`; the v0.3.0 source tarball shipped without CHANGELOG (fixed in v0.3.x patch).
- **`guides/` — executable vs illustrative.** Fake-runnable guide examples are `iex>` blocks: `test/guides_doctest_test.exs` executes every `iex>` block in the *registered* guides via `ExUnit.DocTest.doctest_file/1`, so a wrong signature there is a red test rather than a silent ship. Real-provider, `Phoenix.PubSub`, or external-state examples MUST be ` ```elixir ` fences — `doctest_file/1` ignores fences regardless of fence type, which is how key-dependent snippets stay safe. **Consequence: fenced blocks get ZERO drift protection.** Prefer an `iex>` block for anything Fake can run; fall back to a fence only when the example genuinely can't. `test/guides_test.exs` carries the structural gates (>2 KB, at least one `iex>`, zero audit hits) plus a fenced-API denylist for dead-API references fences can't otherwise flag — extend the denylist whenever you remove a public field or function. Both that file and `test/guides_doctest_test.exs` need the new guide *registered*, or their gates bind on nothing.
- **A repo-wide audit gate whose subject set is a hand-maintained literal MUST assert that literal against a discovered set.** An unregistered subject produces silence, not a failure, so the gate is only as complete as the last person who remembered it — and "remember to add a Module Tree row" is the same faculty that just failed. The literals are `@layer_a` (`test/layer_a_docs_test.exs`), `@public_facade` (`test/allm_facade_doctest_inventory_test.exs`), `@guides` (`test/guides_test.exs`), and `mix.exs`'s own `@guides` — note the last two share a name and carry DIFFERENT membership. Each wants a meta-test comparing the literal against `Path.wildcard/1` or a `lib/` walk, plus an explicit `@excluded %{"name" => "reason"}` map so opt-out stays possible and visible. Assert wiring in BOTH directions — "every guide in the literal is in `docs[:extras]`" is the direction that cannot fail open. Worked examples, three in one build: PHASE_20.1 shipped three Layer A structs unregistered in `@layer_a`, all three carrying banned tokens, fully green; PHASE_20.3's `@public_facade` trap was avoided only because it was in the batch prompt; PHASE_20.7 had to add `test/guides_test.exs` out of its Module Tree because the design's own Test Plan asserted gates that bind only for a listed guide. Contrast the fail-CLOSED gates (`test/groups_for_modules_audit_test.exs`, `test/package_files_extras_consistency_test.exs`), which discover their subjects and merely break the phase's own green-suite criterion.

## Common commands

Toolchain floor: Elixir `~> 1.17`, Erlang/OTP 27+ (see `mix.exs`).

```bash
mix deps.get              # install deps
mix compile               # compile
mix format                # format
mix test                  # full suite (80% coverage threshold in mix.exs)
mix test test/path/to/file_test.exs:42   # single test by line
mix test --only focus     # tests tagged @tag :focus
mix credo --strict        # linter
mix dialyzer              # type check
iex -S mix                # REPL
```

Releases run via `mix run scripts/release.exs <patch|minor|major|version>`. The script enforces clean git, runs all quality gates, bumps `mix.exs @version`, calls `mix hex.publish` interactively, and commits + tags locally on success. The script does NOT `git push` — it prints the exact push command for the maintainer to run separately (separating the irreversible Hex publish from the cheap-and-recoverable origin push). Future Claude sessions MUST NOT manually edit `mix.exs @version` — use the script.

Test-only helpers live under `test/support/` (in `elixirc_paths` for `:test` only) — home for `ALLM.Providers.Fake` fixtures and other test-only modules.

The dev container ships Node, Go, and Elixir/OTP via the `rabdulwahhab/devcontainer-features` asdf features — keep `erlang-asdf` in the features list because `elixir-asdf` depends on it.

## Working on this codebase

- **`README.md` is NEVER modified inside a phase whose Module Tree does not list it as `(MODIFY — N.M, …)`.** At phase N start, `git stash push -- README.md` if README is not in the Module Tree. (The form `git stash README.md` shipped in this rule for months and does not parse — `fatal: subcommand wasn't specified; 'push' can't be assumed` on git 2.43 — and had been copied verbatim into at least one steering doc before being caught. **A shell command written into an instruction file must have been executed once on this toolchain first.**) Documentation polish is a stand-alone `[DOC]` commit or `/asks` ticket. Worked example: PHASE_16.1, 16.2, 16.3, 16.4, 16.5, AND 16.6 each shipped with a 459-line out-of-tree README rewrite breaking `readme_getting_started_test.exs` from green to MatchError; six consecutive phase retros flagged it; the rewrite went unaddressed across all six. Six-phase recurrence promotes from "documented worked example" to "blocking pre-commit invariant."
- Cite spec sections (`§6.3`, `§12.3`, …) in commit messages when the change touches behaviour or spec-defined shapes.
- `ALLM.Providers.Fake` is the canonical test vehicle. Don't reach for network mocks except to test a real adapter's wire shape.
- §31 property-style scenarios are the minimum bar for every implementation.
- `optional: true` in `mix.exs` does NOT skip Hex version resolution — it only governs whether *downstream apps* need the dep. A placeholder constraint against a dep with mismatched published versions still breaks `mix deps.get`. Defer future deps as a code comment (`# :llm_db re-added in Phase 9 …`), not a live constraint.
- **Every bundled provider adapter ships with an examples entry** in `examples/` (provider-neutral helper + numbered scripts + `run_all.exs` orchestrator) and the `/review` step BLOCKS on `ALLM_PROVIDER=<name> mix run examples/run_all.exs` exit 0. Cost ~$0.05–0.10/provider/run. Catches request-shape, per-model-rejection, and endpoint-override bugs that wire-stub fixtures cannot. Worked example: Phase 10.5's first live-validation surfaced three real `lib/` bugs the 1252-test matrix missed; Phase 11.4 confirmed the pattern works for two providers in parallel.
- **Live-gate "blocked-by-pre-existing-failure" state.** When a provider's `examples/run_all.exs` is blocked at a script identifying a pre-existing upstream failure (provider-side endpoint deprecation, project-permission change, paid-tier requirement) documented in a prior phase's commit AND not in current scope, the BLOCKING gate is satisfied by: (i) running the NEW/MODIFIED scripts individually with verifiable success, (ii) leaving the broken script in place, (iii) NOT regenerating the provider's `RUN_OUTPUT_*.md` per the snapshot-defer policy. The commit message AND retrospective MUST flag the deferral with originating-failure phase + commit. Worked example: PHASE_17.3 first hit `dall-e-2` 404 (per `a7b934b`); PHASE_18.5 inherited — Anthropic green end-to-end, OpenAI halted at script 13, examples 14+15 verified individually, `RUN_OUTPUT_OPENAI.md` correctly untouched.
  - **A blocked arm is RE-CHARACTERIZED every phase, never inherited.** Each example script `System.halt(1)`s and `run_all.exs` runs them in one VM, so the FIRST failure kills the run and every script after it is *unobserved*, not passing. A block that moves earlier silently un-tests the tail of the arm, and an arm formally excused from its BLOCKING gate decays into an unexercised one. When claiming the deferral, run the arm's scripts INDIVIDUALLY past the halt and record the full per-script line (`01–09 OK, 10 FAIL, 11 OK, 12 OK, 13 FAIL, 14–18 OK`). Re-test the rule's precondition against the failure you OBSERVED, not the arm's reputation: "documented in a prior phase's commit" must resolve to *that* error, from *that* script, in *that* commit. Any failure that doesn't resolve is filed as a new `[BUG]` with its own reproducer. Worked example: PHASE_20.7 inherited "OpenAI halts at script 13 (`dall-e-2` 404, `a7b934b`)" and found the arm halting at script **10** on `Unknown parameter: 'response_format'` — released v0.4 code broken against the live API (`lib/allm/providers/openai/images.ex:554`), masked behind a documented provider-side 404 since PHASE_17.3 — while `09_ask_user.exs` had separately regressed on the Anthropic arm against its own committed `RUN_OUTPUT_ANTHROPIC.md`.

- **Before concluding a provider key is absent, load the project-root `.env`.** This repo's documented key mechanism is a gitignored `.env` at the repository root (`examples/README.md`), loaded centrally by `examples/_helpers.exs` via the `:env_loader` dev dep. The `scripts/record_*.exs` recorders read `System.get_env/1` bare and therefore report "key not set" in a fully-provisioned checkout — their own diagnostic confirms the wrong conclusion. "The implementer's environment lacks the provider key" means absent **after** that load. Verification blocks MUST write the invocation as it actually runs (`set -a; . ./.env; set +a; mix run scripts/record_…`), not as a bare `mix run`. Worked example: PHASE_20.4 deferred live recording on a false premise and shipped placeholder fixtures under `recorded/`; the key was in `.env` the whole time and the recorder ran clean the moment the file was sourced.

- **`recorded/` fixtures MUST be gated by a per-file negative provenance test that reads the raw bytes.** The `_comment` marker is not only the recorder's refuse-to-overwrite key — it is what makes "these are still placeholders" a test failure instead of a paragraph. Loader helpers call `drop_comment/1`, so any assertion made *through the loader* is tautological and cannot bind provenance. Read the file with `File.read!/1 |> Jason.decode!/1` and `refute Map.has_key?(raw, "_comment")`, one test per recorded fixture, failure message naming the recorder invocation. Worked example: PHASE_20.4's provenance block asserted the marker's *presence* on synthesized fixtures from a raw read (binding) and its *absence* on recorded fixtures through the loader (vacuous) — three placeholder fixtures sat in `recorded/` with a fully green suite.

- **Deferral notes expire, and gate claims are re-verified at commit time.** This file already forbids paraphrasing a post-record state at commit time; the symmetric error is asserting a deferral you no longer have. An Implementation Notes gate line and live-gate status are claims about the tree, not narrative — re-verify both after the review/fix sequence, not at authoring time. Same rule for the repo's own state: **a claim of the form "pinned by a test" or "verified" carries the test's `file:line`.** Across Phases 20.4–20.6 every such claim that carried a cite checked out; both that did not were false. Prose is not evidence about a repo you can grep.

- **Every new provider adapter ships a live wire probe inside its recorder script, and the probe has four parts.** A design's claims about a *provider's* wire were wrong seven times across the three embeddings adapters (OpenAI's token-budget marker on `type` not `code`; Gemini returning no `usageMetadata` and no correlation-id header; Voyage's `{"detail": "<string>"}` FastAPI error envelope, its `x-request-id`, and its `:context_length_exceeded` site) — always researched from published docs, always plausible, only ever falsified by a recorded response. You cannot quote a provider's source, so "quote, don't cite" cannot cover provider claims and the probe is the only falsifier available. Required parts: (1) **negative control** — every "the provider accepts X" arm is paired with an invented-field arm in the same run, because acceptance is evidence of schema membership only once the API is shown to reject unknown fields; (2) **assert, don't narrate** — each arm carries an expected status and any mismatch prints the want/got table to stderr and `System.halt(1)`s *before a single fixture is written*, because `Req.Test`-stubbed wire tests assert what the ADAPTER emits and stay green forever when the provider changes; (3) **record the body, not the status** — any arm whose response shape a fixture asserts writes that body to `recorded/`, error envelopes included; (4) **run behind the overwrite guard** — check every target path first so a fully-recorded tree costs zero live calls. One arm per wire-field-map row the design marks inferred-not-confirmed, plus the control. Canonical: `scripts/record_voyage_embeddings_fixtures.exs` (all four parts, first pass). **The capability's docs sub-phase then enumerates every provider claim it publishes, marked confirmed or inferred** — a wrong claim in a wire-field map is read by one implementer who will shortly hit the wire; a wrong claim in a guide is read by users who will not. The rows most worth an arm are the ones the LIBRARY computes with, not merely reports: `max_batch_size/0` is the arithmetic `ALLM.EmbeddingBatch` chunks by, so a cap too high 400s a call the guide promised and a cap too low silently doubles the user's request count forever.
- **Informational git commands in a multi-agent phase MUST use `git --no-optional-locks`** (or `GIT_OPTIONAL_LOCKS=0`). `/build` runs five review agents in parallel against one worktree, and `git status` / `git diff` / `git log` are not read-only — git takes `.git/index.lock` and rewrites `.git/index` on every stat-dirty refresh. Concurrent writers plus one killed git process truncate the index; the symptom is `git status` reporting every tracked file as staged-deleted and everything else as untracked. The repair is `git reset` (index only). **NEVER `git checkout .`, `git stash`, or `git reset --hard`** — when this fires, the working tree holds an entire uncommitted sub-phase. Five incidents across the Phase 20 build; the remaining exposure is the orchestrator's own commit-time writes, where a stale zero-byte `index.lock` aborted the changelog script after it had already written `HISTORY.md` (recover by verifying no `git` process is running, removing the lock, then committing manually so the changelog entry is not duplicated).

- **`conformance/` is a second Mix project and its gates are not covered by the main project's.** Any phase whose Module Tree touches `conformance/` runs `cd conformance && mix test && mix credo --strict && mix format --check-formatted` as part of Verification. A **pre-existing** static-gate failure in a `conformance/` file the phase does not own is fixed as a separate `[CHORE]` commit *before* the phase commit — never folded into the phase, and never left red across multiple sub-phases. Worked example: `conformance/lib/allm/test/image_adapter_conformance.ex:91-92` has failed `mix format --check-formatted` since Phase 14.1 (`b18ebeb`); no CI exists, so nothing ran that gate for months, and seven consecutive phases each declined to fix it as out-of-tree.

- **Cross-phase discipline covers any change to prior-phase code, not only bug fixes.** The atomicity concern is scope, not defect-ness: a phase's gate can only certify what the phase's Module Tree scopes. Document bugs in the retro and (if a workaround is feasible within scope) record it inline; do NOT fix them in the current phase unless the design scopes the fix in. Worked example: PHASE_10.5 found three `lib/` bugs from Phases 10.2/10.6 during live validation; the implementer correctly worked around them in scripts and the README, did NOT modify `lib/`, and surfaced them in the retro for future-phase pickup. Three narrow exceptions:
  - **Refactors mandated by the two-implementations promotion trigger.** `agent-spec/IMPLEMENTATION.md`'s "Migration on extraction" rule requires an extraction to migrate every inline copy in the same commit, which necessarily touches released code. That refactor is permitted when it is private, behaviour-preserving, leaves every public name in place, and is pinned by the prior phase's own tests — and it is recorded as a `[structural, documented]` deviation. Anything else (renames, signature changes, opportunistic cleanup of a released path) is a separate commit. Worked example: PHASE_20.3 collapsed `augment_image_retry_policy/1` + `augment_embedding_retry_policy/1` onto a shared private `augment_retry_policy/2`, touching the released image path; review verified byte-equivalent behaviour across 11 retry configurations.
  - **The sub-phase that closes a multi-provider family owns the family's internal consistency.** It is the moment a set of independently-built adapters becomes a promised family, and per-phase deferral produces the wrong whole. That sub-phase runs one table-driven equivalence pass over the family's adapters asserting the shared invariants (malformed-input handling, gate ordering ahead of key resolution, `max_batch_size/0` enforcement); divergences it finds are IN SCOPE, and the invariant gets a conformance case so it binds third parties too. Its Module Tree therefore anticipates `lib/` edits it cannot enumerate in advance. Worked example: `OpenAI.Embeddings.embed/2` raises `Protocol.UndefinedError` on a tuple `:input` element where the Gemini and Voyage siblings both return `{:error, %EmbeddingAdapterError{reason: :invalid_request}}` — a behaviour-invariant divergence at a public extension point, masked from façade callers by `Validate.embedding_request/1` and therefore invisible to every test. Four phases each correctly declined to fix it; the ticket named 20.7 as its deadline; 20.7's Module Tree was docs-only and the family shipped inconsistent.
  - **Shipping *safer* than an already-released sibling** is a correctly-scoped deviation AND evidence of a live weakness in that sibling. Record a `[CARRY]` line naming the sibling's file:line and file it in `ASKS.md` in the same pass — "documented in the retro" is not a route while `.work/retro/` holds unapplied files. Worked example: PHASE_20.4's embeddings adapter added `redact_key_material/1` and `sanitize_cause/1` and omitted `body_preview`, while `lib/allm/providers/openai/images.ex` and `lib/allm/providers/gemini/images.ex` still put raw provider messages and 200-char body previews into `Jason.Encoder`-derived error structs that downstream apps persist.
- **`Logger.debug/1` in adapter / hot-path code MUST use the deferred form** `Logger.debug(fn -> "msg #{inspect(...)}" end)` to skip string interpolation when the level is below `:debug`. Mixed forms across `lib/` today; standardize for new adapter code. Worked example: `lib/allm/providers/openai.ex:373`'s strip-reasoning-control debug log.
- **Dispatch trees with three-or-more branches each calling multi-clause downstream get one private function per branch from the start.** SSE chunk mappers are the canonical case but the rule applies to any nested `case`/`cond` where inner arms route to functions returning structurally different shapes (`{:ok, _}` vs `{:ok, _, halt_meta}` vs `{:error, _}`). Adding a single arm to an already-near-threshold (≥7 branches OR ≥2 boolean-composition guards) function forces an in-commit private-predicate extraction — Credo counts boolean operators in clause guards. Pre-empting at design time requires counting branches + operators per touched function (unreasonable burden); accept the in-commit extraction. Worked examples: Phase 11.2 `chunk_to_events/2`; Phase 18.2 `dispatch_partitioned_tool_calls/6`; Phase 18.3 `dispatch_partitioned_stream/3`; Phase 18.4 `per_tool_manual_step?/1`.
- **Decision text drift is a known failure mode; amend the steering doc as part of the implementation commit, not as a follow-up.** When implementing a phase, if a Decision's prose contradicts what the code requires, fix the prose in the same commit and cite the divergence in the message body. Don't ship the divergence and queue a doc-only fix-up commit. Worked example: PHASE_14_image_layer_2_5.md Decisions #3, line 294, #9 each shipped with prose-vs-code drift across 14.1/14.2/14.3 — three follow-up commits. Decision #14 was authored with five file:line cites and shipped zero drift.
  - **Drift discovered under `/build` surfaces in the retro and lands via `/apply-retro` or a follow-up `[DOC]` commit** — not in the implementation commit. The amend-in-commit rule above is written for `/implement` runs where one subagent owns both the `lib/` and steering edits; `/build` orchestrates multiple subagents, none of which owns steering edits.
  - **An `/asks` ticket describing a multi-site defect states the grep that must come back clean, not the number of sites remaining.** "Six of the seven recorders read `System.get_env/1` bare" decays silently the moment a phase fixes one. Write "`grep -L EnvLoader scripts/record_*.exs` must be empty" instead: the ticket then scores itself, survives partial fixes, and tells a future phase exactly when it is done. A ticket that is well-formed and self-scoring can still be **wrong about its own cause** — re-verify the named cause before implementing a ticket's stated remedy.
  - **Release CHANGELOG entries derive from `git diff <prior-tag>..HEAD lib/`, never from a design's prospective "Breaking Changes Summary."** Design tail sections drift from the body during `/ddesign` review. Worked example: PHASE_21's summary claimed two breaking changes; the implementation shipped one, the second having been walked back to a non-breaking metadata-carriage shape in the Type Contracts block without the summary being refreshed.
  - **Type-contract-vs-test-plan drift.** When a design's `Behaviour & Type Contracts` block specifies a constructor as `def new(opts), do: struct!(__MODULE__, opts)` AND the same design's Test Plan asserts `Constructor.new/1 with field: nil raises ArgumentError`, the contract block is wrong: `struct!/2` accepts explicit `nil` for a defaulted field by silently overwriting the default; only `@enforce_keys` triggers `KeyError`. Verify each `raise X` test bullet against the constructor body's actual code path BEFORE submitting the design. Worked example: PHASE_18_DESIGN.md:246 specified `Tool.new/1` as a single-line `struct!/2` pass-through while line 548 required `manual: nil → raise ArgumentError`; 18.1 implementer amended to add an explicit `is_boolean/1` guard in-commit.
  - **Test-bullet-vs-test-vehicle drift.** When a Test Plan bullet asserts a specific error module fires (e.g., `Validate.thread/1 error or AdapterError`), the design MUST cite which test vehicle drives the test (`Fake`, recorded fixture, or live provider) AND which file:line in the vehicle path produces that error. `ALLM.Providers.Fake` is canonical for unit tests; if the asserted error fires only on live providers, tag the bullet `(live-only)` and route to the examples-script live gate. Worked example: PHASE_18_DESIGN.md:597 specified a footgun test asserting `Validate.thread/1 error or AdapterError`; under `Fake`-driven `Chat.run/3` neither validator runs — 18.2 implementer correctly rephrased to a structural-probe assertion.
- **Test-fixture seams discovered in retro N should land in retro-N's fix step, not deferred to N+1.** `:capture_pid` on `FakeImages` was identified in 14.2 retro Finding 3, landed in 14.2 fix step (commit a42d280), then served three new 14.3 test files with zero re-invention. Cross-phase amortization: catch it once, fix it once. Compare with the `:erlang.phash2(script)` cursor footgun (overdue across five retros) — deferred lifts replay verbatim.
- **Phases shipping synthesized wire fixtures MUST commit a recorder script** (`scripts/record_<provider>_<feature>_fixtures.exs`, idempotent per run) AND each synthesized fixture file MUST carry a leading `_comment: "Synthesized…"` marker naming the originating phase. Tests strip the marker via a `drop_comment/1` helper; recorder scripts MUST refuse to overwrite files lacking the marker (i.e., already recorded). Live re-record is a BLOCKING `/review` gate when the implementer's environment lacks the provider key; the phase Verification block MUST list the recorder-script invocation as a discrete step alongside the live-test invocation. CHANGELOG entries claiming live-gate outcomes MUST flag deferral honestly — never paraphrase the future post-record state at commit time. Worked examples: `test/fixtures/openai/images/recorded/` (Phase 15.2 origin), Phase 11.4 / 15.6 / 17.1 / 17.2 / 17.3 — five consecutive deferrals before this rule landed.
- **Snapshot files (e.g., `examples/RUN_OUTPUT_*.md`) MUST be regenerated in the same commit as the live run that produced them, OR not modified at all.** Hand-edited or stale snapshots are worse than missing snapshots — they encode wall-clock timestamps and model output that can't be reproduced from the codebase state at re-run time. When the live BLOCKING gate defers because the implementer's environment lacks the key, snapshot regen also defers. Module Tree rows enumerating snapshot files SHOULD pair them with a "deferred-when-keys-absent" caveat. Worked example: PHASE_17.3 listed `RUN_OUTPUT_*.md` as in-scope; live gate deferred (no keys); implementer correctly skipped snapshot regen.
- **Audit greps for short tokens MUST use `-w` (word-boundary) AND/OR exclude binary-content fixture directories.** A 3-letter substring like `ocr` matches base64-encoded image bytes by chance; design specs proposing `# expected: empty` against a repo with recorded-image fixtures are structurally false unless tightened. Design Verification commands SHOULD be runnable as-written with output matching the repo's actual state. Worked example: PHASE_17 §17.3.3 line 715 proposed `grep -rE '…|ocr|…' lib/ test/ examples/  # expected: empty`; the actual audit hits three recorded-image fixtures (`test/fixtures/openai/images/recorded/*.json`) as base64 noise. **Audit greps MUST also drop generic English tokens and grep the actual identifiers.** A bare `collision` alternation matches synthetic-tool-name collisions, reserved-name collisions, and `adapter_opts` merge-precedence comments — none related to a cursor change. Prefer the concrete key-shape atoms (`allm_fake_cursor`, `cursor_key`, `phash2`) over a prose word.
- **Any process-global mutation from an `async: true` test module is a foot-gun.** This is the general class; the `Logger.configure/1` and `:telemetry.attach/4` bullets below are two instances, and a per-mechanism rule cannot catch the next mechanism. The class covers application env, `:persistent_term`, `System.put_env/2`, a named `Agent`/`GenServer` (e.g. `ALLM.Keys.Store` via `ALLM.Keys.put/2`), and `:telemetry` handler tables. Symptom: a test asserting the *absence* of ambient state (`assert_raise EngineError` for a missing key, `refute_received`) passes at almost every seed and fails at a few. Wrapping the mutation in `setup` + `on_exit` or `try/after` does NOT help — it narrows the window rather than closing it, making the flake rarer and harder to attribute. Fix preference: (a) scope the value to the call (`opts[:api_key]`) instead of the global store; (b) a per-process filter (`test/support/telemetry_capture.ex`); (c) `async: false` on the mutating module. **Detection is static and instant:** `grep -rl 'Keys.put(\|Logger.configure(\|System.put_env(\|:telemetry.attach' test/` must contain only `async: false` modules. Worked example: `test/allm/providers/gemini/embeddings_test.exs:388` failed at `--seed 3333` because `gemini_stream_wire_test.exs:24` and `gemini_vision_test.exs:20` put a `:gemini` key from `async: true` `setup` blocks; the flake survived five phases of `/review`, `/code-review`, `/security-review` and `/retro` all green, and was found only when a later phase's implementer sampled the bad interleaving. Fixed at all four writers in Phase 20.6.

- **Run the suite at a pinned seed as well as the random one — but know what it binds.** `mix test` seeds randomly, so an order-dependent failure passes review indefinitely. Add `mix test --seed 0` to every phase Verification block alongside the plain run. **The seed pins ORDERING, not CONCURRENCY:** it shuffles the order modules and tests are *scheduled* in, and does not control `async: true` pool interleaving, which varies with machine load. So it is not the gate on process-global races — the static grep above is. When a pinned run goes red, `mix test --seed <n> --max-cases 1` is the discriminator: passing serially proves a concurrency race rather than an ordering effect, and any bug report naming a concurrency cause MUST record that experiment plus the `use ExUnit.Case, async:` line of every module it names.

- **`async: true` + `Logger.configure/1` is a foot-gun.** `Logger.configure(level: :debug)` is application-global, not Task-local. Inside a `Task.async/await` wrapper that's there for process-dict isolation, `Logger.configure/1` STILL races with concurrent `async: true` tests — it mutates global Logger state and doesn't restore on Task exit. Use `capture_log([level: :debug], fn -> ... end)` for log-level control (per-process, restored on function exit); reserve `Task.async` for process-dict isolation only. Worked example: PHASE_17.2's detail-drop test at `test/allm/providers/anthropic_vision_test.exs:325, :349` wraps in `Task.async` (correct for the `:allm_anthropic_detail_warned` process-dict latch) but ALSO calls `Logger.configure(level: :debug)` inside the Task — leaks `:debug` globally after the Task exits.
- **`:telemetry.attach/4 + async: true` is a foot-gun, same class as `Logger.configure/1`.** `:telemetry` event-delivery is application-global; a handler attached for `[:allm, :adapter, :retry]` fires for ANY process emitting that event during the test's lifetime, not just the test's own process. Symptoms: `refute_received {:retry, _}` appears to pass but a parallel `async: true` test triggered the handler first; subsequent runs flake. Fix preference order: (a) handler filters `if config.parent == self_pid, do: send(...)` BEFORE forwarding; (b) use `test/support/telemetry_capture.ex` (per-process filter); (c) declare `async: false`. `System.unique_integer/1` for handler id avoids registration collisions but does NOT scope event delivery. Worked example: stream-wire flake at `test/allm/providers/openai_stream_wire_test.exs:428`, `anthropic_stream_wire_test.exs:347`, `gemini_stream_test.exs` — all attach a global handler in an `async: true` module.
- **Public-test-seam helpers carry `@doc false` + `@spec`.** The combination exposes a function for tests + Dialyzer without surfacing in ExDoc. Reach for this pattern when a helper has nontrivial branching (model-conditional encoding, enum-mapping tables, body-shape dispatch) worth exercising directly without driving the full adapter HTTP round-trip. Worked example: `lib/allm/providers/openai/images.ex` exposes nine such seams across Phase 15.1–15.4 (`endpoint_for/1`, `gate_model_op/2`, `to_size_string/1`, `to_json_body/2`, `to_multipart_body/2`, `resolve_image_bytes/2`, `to_image_adapter_error/4`, `decode_response/4`, `mime_type_for_output_format/1`).
